# Knowledge Layer

This directory is reserved for materials derived from reviewed and approved portfolio cases.

The portfolio remains the source of truth. The knowledge layer does not replace case studies and must not introduce unsupported facts, metrics or claims.

## Structure

```text
knowledge/
├── articles/
├── faq/
├── presentations/
├── demos/
├── workflows/
├── architecture/
└── ai-assistant/
```

## Purpose of each section

### `articles/`

Long-form engineering articles for LinkedIn, Medium, Dev.to and the Gubenko AI website.

### `faq/`

Verified answers to recurring questions from colleagues, clients, interviewers and project stakeholders.

### `presentations/`

Executive and technical presentations generated from approved case studies.

### `demos/`

Demo scripts, walkthroughs, sanitized recordings and reproducible demonstration scenarios.

### `workflows/`

Visual and textual descriptions of project processes, data flows and operational sequences.

### `architecture/`

Architecture decision records, alternatives, trade-offs, constraints and implementation notes.

### `ai-assistant/`

Approved project knowledge prepared for retrieval by the future website AI assistant. This section must contain source references and exclude confidential or security-sensitive information.

## Publication workflow

```text
Verified project evidence
        ↓
Approved portfolio case
        ↓
Knowledge material draft
        ↓
Technical and privacy review
        ↓
Human approval
        ↓
LinkedIn / website / presentation / AI assistant
```

## Current status

The directory structure is defined now, but content production begins only after the corresponding portfolio case and its evidence package have been reviewed.
