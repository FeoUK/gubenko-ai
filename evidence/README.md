# Engineering Evidence Library

This directory contains evidence packages for selected projects in the **Alexander Gubenko — Applied AI Systems Architect** portfolio.

The purpose is to separate marketing statements from verifiable engineering material. Each package records the problem, architecture, decisions, implementation boundaries, security model, deployment approach, available artifacts, and evidence still to be collected.

## Evidence principles

- Do not claim production results without a traceable artifact.
- Separate implemented capabilities from planned work.
- Redact customer names, credentials, internal addresses, secrets, and sensitive operational details.
- Prefer reproducible artifacts: diagrams, sanitized configuration fragments, screenshots, logs, metrics, pull requests, and deployment notes.
- Mark missing material as `pending evidence` rather than filling gaps with assumptions.

## Package maturity

1. **Scaffold** — structure and collection plan exist.
2. **Draft** — architecture and engineering narrative are documented.
3. **Evidence-backed** — claims are linked to sanitized artifacts.
4. **Public-ready** — reviewed for accuracy, confidentiality, and presentation quality.
5. **Published** — linked from the Service Portfolio and external profiles.
