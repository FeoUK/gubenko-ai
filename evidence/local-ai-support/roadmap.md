# Roadmap

## Phase 1 — Documentation baseline

- Complete the engineering narrative.
- Review terminology and contribution statements.
- Confirm which implementation details may be published.
- Maintain a clear distinction between implemented and planned capabilities.

**Status:** in progress.

## Phase 2 — Publishable demonstration

- Prepare a synthetic or public technical document set.
- Build a reproducible end-to-end demonstration.
- Capture source-aware answers and insufficient-context behavior.
- Add architecture and deployment diagrams.

## Phase 3 — Sanitized operational evidence

- Publish configuration fragments without secrets or internal identifiers.
- Document health checks, logs and backup behavior.
- Record hardware and runtime versions.
- Add repeatable deployment instructions for the demonstration environment.

## Phase 4 — Quality evaluation

- Create a representative question set.
- Define retrieval relevance and answer-grounding criteria.
- Test unsupported questions, stale content and conflicting versions.
- Publish methodology together with results; do not publish isolated numbers without context.

## Phase 5 — Enterprise evolution

Potential future capabilities, subject to project requirements:

- hybrid semantic and keyword search;
- reranking;
- document-version awareness;
- SSO and role-aware retrieval;
- department-specific knowledge spaces;
- multilingual retrieval and generation;
- feedback-assisted quality review;
- controlled agent workflows for support operations.

## Public-ready exit criteria

The package can be marked public-ready when:

- every major claim has a status and supporting artifact;
- diagrams match the documented design;
- confidential details have been reviewed and removed;
- screenshots use approved data;
- configuration examples contain no secrets;
- metrics include test conditions and methodology;
- links from the Service Portfolio resolve correctly.
